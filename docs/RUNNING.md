# 运行与操作说明

## 1. 环境与首次运行

- 网页壁纸：Windows、Wallpaper Engine，完整项目文件。无需 Node.js 或 npm。
- 可选控制器：Python 3.9+、Windows 自带 Windows PowerShell。推荐安装 Python 时启用 `py` 启动器。
- 日志与连接码会写入 `tools`，因此目录需要当前用户可写。建议放在普通用户有权限的磁盘目录，不要以管理员身份运行。
- 联网歌词/封面需要能够访问 AMLL、LRCLIB、MusicBrainz 和 Cover Art Archive；服务失败不会阻止基础歌曲信息显示。

将 `index.html` 导入 Wallpaper Engine 网页壁纸编辑器，保存并应用；启用媒体集成后在播放器中播放音乐。先确认歌名、歌手能显示，再配置控制器。频谱使用独立的音频接口，需要选择正确的音频设备。

## 2. 连接码到底取哪一份

控制器运行时读取**它自己的 `tools/.connection-code`**。文件不存在时，Python 控制器第一次启动会生成一个；再次启动沿用原码。不要随意删除或重新生成。

例如从 `G:\ai-video\Kurisu-Evening-Player\tools\start-controller.cmd` 启动，就取同目录的 `.connection-code`。本机当前几份副本的码已人工对齐，但代码不会永久保证以后新复制的目录仍一致。

在 Wallpaper Engine 主窗口选中这张壁纸，将连接码粘贴到右侧“本机播放控制连接码（可选）”。这是 Wallpaper Engine 保存的用户属性，不是浏览器的设置。桌面壁纸通常不接收键盘输入，请勿在桌面弹窗中反复尝试打字。

连接码通常配一次即可。电脑重启后需要的是控制器重新运行，而不是重新填写连接码。提示“连接码不匹配”表示控制器在线，但保存的码不对；提示“控制器未连接”也可能是没启动、没有填写码或无法访问本机端口。

## 3. 手动启动与后台运行

| 文件 | 用途 |
|---|---|
| `tools/start-controller.cmd` | 在窗口中运行，首次使用可直接看到连接码。自己启动的控制器会在关闭该窗口后退出 |
| `tools/start-controller-background.cmd` | 隐藏控制器窗口，返回后控制器继续在后台运行；失败时保留提示窗口 |
| `tools/start-controller.ps1 -CheckOnly` | 只检查 Python 和必需文件，不启动控制器，不创建连接码或启动项 |

新启动器会检查端口和连接码：已有同码控制器时直接退出，不再启动第二份；端口被其他服务或异码控制器占用时报告错误。不会终止或替换现有进程。若控制器已在后台运行，再双击窗口启动脚本只会提示它已运行并显示本目录连接码，不会把后台进程搬到新窗口中。

日志位置：`tools/.logs/launcher.log`、`controller.out.log`、`controller.err.log`。后台不输出连接码；请仍从 `.connection-code` 读取。launcher.log 超过约256KB会保留一份 `.old`；控制器输出日志在下一次成功尝试启动时重新写入。

需要停止自己手动打开的控制器时关闭它的窗口；后台控制器会在注销/重启后退出。若需要在任务管理器停止，先用 launcher.log 中的 PID 确认对应进程，不要结束所有 Python 进程。

## 4. 安装开机启动

这里的“开机启动”具体指**当前用户登录 Windows 后运行**，不是系统服务，也不会在登录前启动。

1. 先固定项目位置，例如 `G:\ai-video\Kurisu-Evening-Player`。确认 Python 已安装，手动启动及连接成功。
2. 双击 `tools/install-autostart.cmd`。看到 `Autostart installed` 表示安装成功。
3. 下次登录，启动器会在后台启动本目录控制器。安装脚本本身不会立即启动控制器；当前想后台运行，可用 `start-controller-background.cmd`。
4. 如希望壁纸同时出现，在 Wallpaper Engine 自身设置中启用它的自动启动。酷狗等音乐软件是否自启由你另行设置。

实现方式：在当前用户启动文件夹（`shell:startup` 对应的位置）创建 `Kurisu Evening Player Controller.lnk`。快捷方式指向本目录 `start-controller.ps1`，使用绝对路径并隐藏 PowerShell 窗口；支持含空格的项目路径。无需管理员、计划任务、注册表服务或修改系统全局执行策略。启动参数中的 ExecutionPolicy Bypass 只用于这次 PowerShell 进程；受组织策略管理的机器仍可能被限制。

安装可重复运行，只更新该项目的同名启动项。若发现同名但非本项目创建的快捷方式，脚本会拒绝覆盖。请只从你选定的一个目录安装；从另一副本重新安装会把启动项改指向那个副本。

- 检查：双击 `tools/autostart-status.cmd`，查看是否已安装以及绑定目录。
- 取消：双击 `tools/uninstall-autostart.cmd`，只移除本项目启动项，不删除连接码、壁纸或日志，也不停止当前控制器。
- 移动/重命名目录：移动后从新目录重新运行安装脚本；否则原快捷方式会指向失效位置。
- 删除项目：先取消自启，再自行处理文件。
- G盘登录时尚未挂载、Python失效、目录权限不足或安全软件禁用启动项时，自启可能失败；恢复条件后可以手动运行后台启动脚本。

开发测试参数：`manage-autostart.ps1 -Action Install|Remove|Status -StartupDirectory <测试目录>` 可以在测试目录验证快捷方式，不影响真实启动项。正常使用无需这个参数。`start-controller.ps1 -Port` 仅供隔离测试，正式壁纸固定连接18743。

## 5. 时间、歌词与译文

时间优先使用有效的系统媒体时间。酷狗某些版本的系统时间为0，控制器会只读访问酷狗主窗口的播放栏时间控件；这要求该窗口可被读取。关闭到托盘或控件变化可能失去读取能力，打开酷狗主窗口再试。

同一首歌已取得时间后，短暂失败不会清空总时长；超过7秒不再继续推算。恢复读取后校准。切换到新歌则必须清空上一首的时间，不能把旧进度继续显示给新歌。

AMLL、酷狗和 LRCLIB 并行查询，先显示可用歌词，再用已有中文译文升级；同等结果优先 AMLL。AMLL 搜索会展开规范化标题、歌手拆分和词库别名，并兼容行内与文件头的两种 TTML 译文格式。匹配依据歌名、歌手及其他可用元数据；没有匹配时显示简短原因。当前界面显示一行原文和可用副行（可能是译文或罗马音），没有上一句/下一句列表，也不提供自动机器翻译。无需注册 AMLL API Key。

酷狗有时只向系统发送歌名，不提供歌手，原来会因此不查询歌词。已连接控制器可从酷狗当前歌名/歌手标签补充；没有控制器时，AMLL 仅在较长完整标题对应唯一歌手时自动确认，短歌名或多歌手同名情况不猜测。当前显示“正在查找歌词”“缺少歌手信息”“未找到匹配歌词”或“歌词服务暂时不可用”，用于区分问题；单个来源等待超过20秒会退出并保留其他结果。

有可靠时间时歌词跟随进度；没有时间时可以显示歌词，但不能可靠地跟随播放。歌词源只有原文时只显示原文。标题附带中文别名、现场/翻唱版本、歌手写法、词库收录和网络失败都会影响结果。

2026-09-26 用当前 Provider 真实联网验证：YOASOBI《夜に駆ける》取得56行中文译文，《アイドル》取得78行，并验证组件译文行可见。imase《逃避行》当次未从 AMLL 匹配到。这些是当次结果，不保证所有歌曲或未来接口始终有译文。

## 6. 常见问题

| 现象 | 检查方法 |
|---|---|
| 有歌名和歌词，但没有时间、按钮灰色 | 看连接状态；启动控制器、核对正在运行的目录及其连接码 |
| 连接码不匹配 | 用当前控制器的 `.connection-code` 更新 Wallpaper Engine 右侧属性，不要取旧包里的码 |
| 已连接但读不到酷狗时间 | 打开酷狗主窗口，确认播放栏显示时间；某些版本可能不支持现有控件读取 |
| 时间停住 | 歌曲可能暂停，或采样中断后已停止推算；恢复主窗口读取后会校准 |
| 有日文，没有中文 | 当前匹配结果可能没有翻译；先用文档列出的原版歌曲测试 |
| 歌词完全没有 | 检查“联网查询”和“显示歌词”，等待请求；也可能是无匹配、纯音乐或词库/网络不可用 |
| 歌词整体提前/落后 | 在右侧调整歌词时间偏移，范围±5秒，正值提前 |
| 封面不高清 | 查询失败时使用系统缩略图；都没有时用默认背景裁切图 |
| 浏览器演示正常，桌面未变 | Wallpaper Engine 加载的是导入副本；把更新同步到实际项目目录并重新应用 |
| 开机后没连接 | 用自启状态脚本检查路径；检查 Python、磁盘是否就绪及 `.logs` |
| 端口被占用 | 启动器拒绝重复占用18743；先确定运行的是哪份程序，别反复启动不同副本 |

## 7. 更新、备份与分享

更新前保留正在使用的 `tools/.connection-code`，不要用其他电脑的码覆盖。网页变更需要同步到 Wallpaper Engine 实际项目副本并重新应用；控制器 Python/C#/PowerShell 文件变更需要重启对应控制器，前端文件更新通常不需要重启它。

自启快捷方式绑定目录，不绑定文件内容；在原位置更新脚本一般不用重新安装自启，移动目录才需要。不要把运行日志、私有码和 `__pycache__` 打包上传。项目提供 `.gitignore`，但手动 ZIP 不会自动遵守它，打包仍需排除。

开发者验证脚本放在项目外的 `Kurisu-Evening-Player-QA`，验证记录见 `VALIDATION.md`。正式项目没有 npm test；控制器可用 Python 标准库测试，界面回归使用本机 Playwright/Edge 环境。自动化中不要用真实媒体按键改变用户正在播放的音乐。
